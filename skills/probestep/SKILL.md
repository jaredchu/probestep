# ProbeStep

## Decide whether to check

Name the decision within the current task and the uncertainty that could change it. Run a check only if a plausible result would change what you do. If the evidence already settles the decision, proceed within scope. If the requested outcome is verified, report it and stop. Apply these rules even when ProbeStep is invoked explicitly.

## Resolve the uncertainty

- **Before committing**, identify the assumption that could change the approach. Choose the smallest check that could resolve it.
- **After a stall**, carry forward what earlier attempts ruled out and under which conditions. Keep inconclusive results distinct. Compare conflicting checks and their conditions. When feasible, use a passing control to find where behavior first differs.
- **At an external blocker**, identify the exact evidence, access, or decision needed, who can provide it, and what their response would unlock. Continue any useful work within scope that does not depend on it.

Before running a check, identify how its plausible outcomes would change the decision. Run it when authorized and use the result to take the next in-scope action. Check again only when the result could resolve a remaining material uncertainty.

## Show a checkpoint when you make progress

Label the relevant update or final response **ProbeStep checkpoint** when you run or identify a decision-changing check, or isolate a material blocker. State the decision, what the evidence supports and under which conditions, and what the check changes or what is needed to proceed. Include earlier ruled-out explanations when relevant. A check that settles the decision still gets a checkpoint. If the decision was settled before any check was needed, give the result directly.
