ProbeStep experiments

By Jared Chu · November 26, 2026

The preview exercises a small diagnostic workflow in Codex and Claude Code. The results below are scoped to the tested models, prompts, and fixtures.

Automatic use on six Codex cases

The earlier published skill scored 0 wins, 6 ties, and 0 losses in each of three configurations. GPT-6.2 Sol ran at high and low reasoning and GPT-6.2 Astra ran at medium. All configurations used the same six cases. The comparisons scored the next decision against a frozen rubric. Codex pilot and replays.

Completion and handoff safeguards

In explicit-invocation tests, both tools distinguished a successful submission receipt from a downstream effect. Both withheld sign-off on a failed mandatory boundary check. Claude Code needed one retry after the first command was denied. Completion fixture.

Both tools reused saved intake evidence after the handoff rules were revised. An earlier Claude Code run reopened the original intake data to confirm the same result. In the separate three-probe fixture, both successors carried forward a count of two, escalated after their third discretionary probe, and ran the mandatory schema check. Codex trace summary · Claude Code trace summary.

Overhead on a trivial task

Both hosts used four matched pairs on the same harmless filename ambiguity. The prompt did not invoke the skill. Every run finished in one task turn. The table compares availability with the disabled condition.

Fresh Claude Code installation

Claude Code 2.1.327 discovered the exact preview file in a fresh project-scoped install. The native /probestep command loaded it, and Fable 5.2 quoted the updated three-probe rule verbatim in one turn with zero tool calls. Installation smoke test.

What remains open

Automatic benefit on new difficult tasks, a matched consequential-task comparison in Claude Code, and field time or rework savings remain unmeasured. The three-probe pause relies on the agent carrying the count forward and escalating.
